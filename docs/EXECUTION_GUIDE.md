# Execution Guide

This document is the canonical run order for the Power Quality Disturbance Classification project. Run commands from the repository root (the directory containing main.py).

## 1. Clone the intended repository and branch

~~~bash
git clone https://github.com/Vishal-ak/Major-Project-EE.git
cd Major-Project-EE
git switch Something-New
git pull --ff-only origin Something-New
~~~

Confirm the active branch before editing or running:

~~~bash
git branch --show-current
git status
~~~

The branch should be Something-New. Do not push these project changes to main or to a different fork.

## 2. Create the Python environment

Use Python 3.9 or later. A virtual environment keeps project dependencies isolated.

### Windows PowerShell

~~~powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
~~~

If PowerShell blocks activation, use the command below for the current terminal session, then activate again:

~~~powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
~~~

### Linux or macOS

~~~bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
~~~

## 3. Prepare and verify the dataset

Download the SEED-PQD dataset from the Zenodo record linked in the README. Keep the original archive as the source copy. Extract the XPQRS class CSV files into:

~~~text
data/raw/XPQRS/
~~~

The loader expects the dataset in the repository's configured data directory. Do not rename class CSV files unless the loader and class mapping are updated together.

Expected dataset characteristics used by this project:
- 17 disturbance classes
- 1,000 waveforms per class (17,000 total)
- 100 samples per waveform
- 5,000 Hz sampling rate
- 50 Hz fundamental frequency
- One 20 ms cycle per waveform

Before starting a full run, verify that the expected class CSV files are present and that the dataset archive has been extracted completely. If the loader reports missing files, resolve the dataset path first rather than changing the classifier.

## 4. Execute the project in this order

### Step 1 — Main feature extraction and clean benchmark

~~~bash
python main.py
~~~

This is the primary pipeline. It loads the dataset, creates representative signal visualizations, loads or extracts the 66-feature matrix, validates the matrix, writes the feature dictionary, and runs the A–L XGBoost comparison.

The expected feature families are:
- FFT: 7 features
- DWT: 20 features
- Statistical time-domain: 7 features
- STFT: 8 features
- WPT: 16 features
- HHT: 8 features

The combined feature matrix has 66 numerical features plus class_label and class_index metadata columns (68 columns total).

Important cache behaviour: main.py currently reuses data/processed/extended_features.csv when it exists and its shape is (17,000, 68). A matching shape does not prove that the cache was generated by the current feature-extraction code or settings. Delete or move this CSV and rerun main.py only when you intentionally need to regenerate features, such as after changing extraction code, dataset content, or extraction parameters. Keep a backup if the cached matrix is important.

### Step 2 — Single-waveform inference (after Step 1)

~~~bash
python predict.py
python predict.py --class_name Sag
python predict.py --csv data/raw/XPQRS/Transient.csv --row 0
~~~

The inference script loads the Config-L compatibility model and scaler created by the clean training pipeline. Run main.py first so the expected model and scaler artifacts exist. The custom CSV must contain one waveform per row and the selected row must contain exactly 100 finite samples.

The script reports measured latency on the machine where it runs. Do not treat a single run as proof of a hard real-time guarantee; benchmark repeated runs on the intended deployment hardware before making a latency claim.

### Step 3 — AWGN robustness evaluation (after Step 1)

~~~bash
python run_noise_robustness.py
~~~

This runner loads the feature matrix, executes the corrected clean benchmark, retains its split and fitted model/scaler artifacts, and evaluates the held-out test signals with AWGN at 40, 30, and 20 dB SNR. It writes the clean/noisy comparison outputs and figures under outputs/.

The current implementation uses a fixed random seed and one noise realization per SNR. Treat these results as a preliminary single-realization stress test, not a Monte Carlo robustness estimate. A stronger study should repeat each SNR condition across multiple independent noise seeds and report mean and dispersion (for example, standard deviation or confidence intervals).

### Optional — Legacy FFT + DWT milestone

~~~bash
python run_milestone_1.py
~~~

This is a separate earlier milestone/baseline. It is not a prerequisite for the extended 66-feature pipeline, inference, or AWGN evaluation.

Exact output names can change as the pipeline evolves. Use the filenames printed by the scripts and confirm timestamps after each run.

## 6. Troubleshooting

- ModuleNotFoundError: activate the virtual environment and rerun pip install -r requirements.txt.
- Dataset/file-not-found error: check the extracted class CSV files and the configured data path.
- Feature matrix shape error: inspect the CSV header and row count. Regenerate it only after confirming that the dataset and extraction settings are correct.
- Missing inference model or scaler: run python main.py successfully before predict.py.
- Missing feature matrix in the noise runner: run python main.py first.
- Memory or runtime problems: close other heavy applications, avoid launching multiple training runs simultaneously, and inspect the traceback before changing parallelization settings.
- Unexpected metrics: verify the active branch, dataset version, feature cache provenance, random seed, and output timestamps. Do not overwrite historical result tables with unverified values.

## 7. Reproducibility checklist

Before reporting results, record:
1. Repository URL, branch, and commit SHA.
2. Python version and installed dependency versions.
3. Dataset source/version and file integrity.
4. Whether the feature matrix was freshly extracted or loaded from cache.
5. Split seed, test fraction, and cross-validation settings.
6. The exact output CSVs and figures generated by that run.
7. For AWGN, the SNR values and independent noise seeds/trials used.

The corrected cross-validation implementation and revised noise runner have been committed to this branch, but they have not been runtime-validated in this environment. Run the commands above locally and retain the complete terminal output. Do not describe the revised metrics as verified until a fresh run completes successfully.
